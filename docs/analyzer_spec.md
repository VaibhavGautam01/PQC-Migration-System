## Command line and dashboard

    python run_pipeline.py --input path/to/stego.png --public-key 15,7

Exit codes: 0 = pipeline complete, 1 = the report broke a rule, 2 = file not found, 3 = stopped at a stage that is
not built yet. The report is written to outputs/tmp_analyzer_report.json (not tracked by git).

The dashboard gets a "Stego Analyzer" page: upload, then the same stages with the result of each one.

## The public key is an input (design change found in Week 6)

The plan said the analyzer reads the modulus size from the image. It cannot: in the toy stego format
(extras/stego_attack_toy.py) the image holds only the hex ciphertext blocks, and the block width is the same
for N = 15, 21 and 35. The attacker in the plan (Section 5) holds the stego image AND the public key, so the
analyzer takes the public key (n, e) as a second input: --public-key N,E on the command line and two fields on
the dashboard page. Without it the analyzer still detects, extracts and recognises an ML-KEM payload by length,
but it does not attack an RSA payload and says "modulus unknown, give the public key". It never guesses N.
Sir has not been asked about this yet.

## Stages

| # | Stage | Module (owner) | Result it hands on |
|---|---|---|---|
| 1 | Accept the image | stego_analyzer/pipeline.py (Tarun) | file name, SHA-256, size |
| 2 | Detect the hiding method | detect_method.py (Vaibhav) | lsb or clean_or_unknown (trial extraction with the pinned extractor; no confidence claimed) |
| 3 | Extract the blob | extract.py (Vaibhav) | the hex text as bytes; calls the pinned project's extract_lsb by path, never edits it |
| 4 | Identify the cipher | cipher_identify.py (Uday) | textbook RSA (needs the public key), ML-KEM + AES-GCM (by length), or unrecognised |
| 5 | Pick the technique | reuse src/quantum_mapper.py | Shor for RSA, ECC, DH; Grover for AES, SHA |
| 6 | Attack or estimate | quantum_stage.py, estimate.py (Yatharth); attack_classical.py (Vaibhav, not built) | one of the five result states below |
| 7 | Score and report | pipeline.py and schema.py (Tarun); report.py exports (Uday) | risk score from the SAME engine, evidence links, CSV and PDF |

Rules that apply to every stage: pinned repositories are never edited; analyzer code lives in stego_analyzer/;
test images are generated by script from our own projects and are never committed; anything outside our formats
is "unrecognised" and is never guessed.

## Result states

| State | Meaning | Evidence required |
|---|---|---|
| broken_toy | the real Shor circuit measured a period, N was factored, the message was decrypted | a record in data/quantum_runs.json, label "Aer simulator, toy size" |
| broken_classical_small_key | the existing small-key attack succeeded on a local or pinned copy | tool, version and time |
| vulnerable_estimate | Shor-class algorithm but the key is too large to run here | logical qubits 2n+3, Q4 and published figures, labelled ESTIMATE; never a time to break |
| resists | ML-KEM + AES-GCM payload: extraction works, nothing to factor | the cipher identification |
| unrecognised | hiding method or cipher not in our formats | none; no guess is made |

## How a result becomes a score

The analyzer does not have its own formula. It builds one layer configuration and calls the engine
(src/risk_score.score_layer), so its score equals the engine's score for the same configuration.

| Identified cipher | category | construction | exposure | modulus_bits |
|---|---|---|---|---|
| textbook RSA | shor_broken | no_padding_deterministic | from the hiding method (below) | read from the blob |
| OAEP-style RSA | shor_broken | oaep (F4 = 5, as in the plan's worked value) | as above | read from the blob |
| ML-KEM + AES-GCM | nist_pqc | aead | as above | not applicable |
| unrecognised | not scored | not scored | not scored | not scored |

Exposure (F6) follows the hiding method: LSB has no secret, so keyless; XOR-LSB is keyed but the header scan can
still find the data, so bypassable. This is an assumption in code (pipeline.exposure_for); Yatharth to confirm.
Reference values the tests check: textbook RSA 256 bits, keyless = 91.9; OAEP 2048 = 50.8 (the plan's worked
value); ML-KEM-768 + AES-256-GCM = 4.7. "Unrecognised" is shown as "not scored".

Routing (pipeline.choose_route): textbook RSA with N up to 35 goes to the Shor stage (TOY_MAX_N, 221 if the stretch
goal is met); other textbook RSA up to 96 bits goes to the small-key attack (SMALL_KEY_MAX_BITS, Vaibhav to
confirm); larger goes to the estimate. OAEP-style always goes to the estimate (the padding cannot be undone with a
toy modulus). ML-KEM + AES-GCM resists.

    {
      "schema_version": 1,
      "created_utc": "2026-11-20T10:00:00Z",
      "input": {"file": "stego_01.png", "sha256": "...", "bytes": 123456},
      "hiding": {"method": "lsb | xor_lsb | clean_or_unknown", "confidence": 0.93,
                 "test_set_error_rate": 0.04, "features": {"ones_fraction": 0.5, "chi_square": 12.3}},
      "extraction": {"ok": true, "blob_bytes": 128, "source": "pinned function, by path"},
      "cipher": {"kind": "textbook_rsa | oaep_style | ml_kem_aes_gcm | unrecognised",
                 "modulus_bits": 6, "evidence": "blob length and structure"},
      "technique": {"algorithm": "shor | grover | none", "reason": "RSA is broken by Shor's algorithm"},
      "attack": {"state": "broken_toy | broken_classical_small_key | vulnerable_estimate | resists | unrecognised",
                 "run_id": "q2-shor-N35-a2-...", "label": "Aer simulator, toy size",
                 "recovered_message": "..."},
      "estimate": {"logical_qubits_2n_plus_3": 4099, "published": "Gidney and Ekera 2021, ESTIMATE, not measured"},
      "score": {"quantum": 79.1, "classical": 61.0, "overall": 71.8, "band": "High", "weights_version": "v1.0"},
      "limits": ["accuracy outside our formats is unknown", "a weighted score, not a probability"]
    }

Rules for the report: recovered_message is filled only for broken_toy and broken_classical_small_key;
an estimate never carries a time; every quantum result carries its label; score is absent for "unrecognised".

## Test set and validation (SA1, SA6)

- A script generates a labelled set from our own projects: LSB, XOR-LSB and clean images; textbook RSA,
  OAEP-style and ML-KEM payloads; several toy N (15, 21, 35).
- Measured and published: detector accuracy, identifier accuracy, error rate on the test set.
- Consistency test: the analyzer's score for an image equals the engine's score for the same configuration.
- Change-the-question test: two images that carry different N give different factors with no code change.
- Static guard (rule 8) covers stego_analyzer/quantum_stage.py: it must call the Q2 circuit builder with the N
  read from the image and must never factor N classically first.
- Break-the-analyzer tests: corrupted images, clean images, images from other tools, adversarial input.
  Failures are recorded honestly.

## Dependencies and fallback

The Shor stage needs the Q2 circuit (N = 15, 21, 35) with its evidence records. Both exist now. If Q2 slips,
the analyzer ships as detect, extract, identify and estimate only, and the report says so.
